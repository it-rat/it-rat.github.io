# Where the site stands for search and AI readers

Written 2026-07-26. This file exists so the next person, human or agent, does not
have to reconstruct today's decisions from commit messages.

## Baseline

**2026-07-26 is the zero point for search telemetry.** Before that date the site
had never been verified anywhere, so there is no earlier data to compare against.

- Google Search Console: `it-rat.com` as a **Domain property**, verified by DNS TXT
  on Cloudflare (where the nameservers are). Chosen over URL-prefix because
  `http://` and `www.` both 301 to the apex and would otherwise be three properties.
- Bing Webmaster Tools: same domain, ten URLs submitted manually.
- **Open:** IndexNow. A key generated in Bing plus a step in the deploy workflow
  would notify search engines on every publish. Nothing about it is metered.

## What is in place

| Layer | Where it lives | Regenerated by |
|---|---|---|
| Shared footer, from the STACK registry | every page | `tools/footer.py` |
| JSON-LD: Organization, WebSite, SoftwareApplication, TechArticle, BreadcrumbList, CollectionPage, DefinedTermSet, FAQPage | every indexable page | `tools/seo.py` |
| 38 FAQ answers as native `<details>` | 11 pages | `tools/faq.py` |
| Markdown mirrors, `llms.txt`, `llms-full.txt`, `mcp-index.json`, `rel=alternate` | site root | `tools/llms.py` |
| Per-page Open Graph cards | `assets/og/` | `tools/ogimages.py` |
| Docs as an MCP server (stdio) | `mcp/it-rat-docs.mjs` | hand-written |
| Remote MCP endpoint, **written but not deployed** | `mcp/worker.mjs` | hand-written |

Run all of them from the repo root after editing pages:

```
python3 tools/footer.py && python3 tools/faq.py && python3 tools/seo.py && python3 tools/llms.py
```

`tools/ogimages.py` needs Chrome and only has to run when a service is added or renamed.

## Rules that produced this, worth keeping

- **Structured data is derived from the visible page, never hand-written beside it.**
  `tools/seo.py` reads the FAQ and the glossary back out of the HTML, so the marked-up
  answer is the answer on the page by construction.
- **Nothing a crawler needs is left to JavaScript.** The service rail, the footer chips
  and the ticker counters are real HTML; they used to be script output, and a crawler
  that does not run scripts was reading an empty rail and a literal `0`.
- **Guides explain the field, not the products.** No pricing, no case studies with client
  numbers, no named-competitor comparison pages, and no setup instructions inside a guide.
  Comparisons stay at the level of approaches; setup stays in the service repositories
  where it can be versioned.
- **Titles at most 70 characters, descriptions between 25 and 160.** Measure every page
  at publish time, not once as an audit: on 2026-07-26 seven titles and nine descriptions
  shipped over the limit precisely because the check was run once and never re-run.

## What to look at, and when

Give it two to three weeks, then:

- Google → **Pages** for indexed versus not indexed, and **Performance** for which queries
  the six guides pick up. Expect some pages to sit in "Discovered, currently not indexed"
  for a while: that is a new domain with few external links, not a defect.
- Bing → **Search Performance**, and **AI Performance (BETA)**, which is the only place
  the machine-readable work shows a number.

The seventh guide should be written against those queries rather than guessed at.
